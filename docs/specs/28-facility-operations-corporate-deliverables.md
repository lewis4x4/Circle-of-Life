# Corporate deliverables and immutable meeting views

COL-160 covers exactly AL-M09, AL-Q01 and AL-C08: Census EOM review (`hfo-al-m09-01`), unresolved FPC EOM review (`hfo-al-m09-02`), Trust EOM review (`hfo-al-m09-03`), Mail trust statement (`hfo-al-q01-01`) and Contract copy to confirmed recipient (`hfo-al-c08-01`). FPC has no approved subject or source. Contract copy has no canonical native document classification or current recipient. Both remain visible and unavailable; neither may create a task or packet by inference.

An expected submission is uniquely identified by organization, facility, component, explicit period, subject kind and null-safe resident identity. Task, request key, recipient, coverage version and packet version are excluded. Coverage sets are append-only versions scoped to the same subject identity. Corrected provenance or an A→B→A site-set change appends a version; an exact no-change registration does not.

Prepared versions capture an authorized native Census, Trust, exact Stand Up revision or approved native document classification. The database builds captured JSON; callers cannot submit snapshots, hashes, actors or sequence values. The selected family alone determines no-change identity, so another finance family cannot create a false version. Each capture is limited to 512 KiB. Live reads return the current site payload only, current metadata for other expected sites, and independent cursors for older versions and events. Responses and pages are limited to 1 MiB.

Prepared, sent, received, accepted and rejected are distinct, non-regressing states bound to one immutable packet version. External facts retain date-only or offset timestamp precision and attributable channel/source evidence. Comparable dates must be ordered. Rejection requires prior receipt and an existing same-task current-owned issue. Missing requires no prepared version; late requires a passed documented due date and an unreceived latest version; rejected follow-up requires the latest version to be rejected. Issue state is current; the event keeps immutable issue revision, owner, backup and next action evidence.

Meeting capture stores a bounded current-version projection of the recorded expected-site set, including missing sites. Capture time is server-owned. Actual presentation date/time and provenance are optional and separate. Corrections never rewrite an earlier meeting view. Every version and meeting member is reauthorized on every read; one inaccessible expected or historical member withholds all protected detail.

Front Office receives no corporate packet data. The only compatible boundary remains the existing `standup_weekly` allowlist and signed complete-snapshot protocol. COL-160 makes no network request and does not register or enable a new dataset.

Public authenticated RPCs are `corporate_deliverable_snapshot`, `corporate_deliverable_history` and `corporate_deliverable_command`. Application routes apply current-actor revalidation, strict cross-field schemas, no-store responses, deterministic 4xx bounds and byte-identical retry only for uncertain transport/server outcomes. The organization-level unresolved endpoint exposes FPC to owner/org_admin without a fabricated task or activation action.
