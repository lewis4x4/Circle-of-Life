# COL-148 UI survey (read-only, 2026-09-10, source at the COL-145 tip)

Made before any COL-148 code, to settle the contract for the staff Today, Upcoming and History workspace (HFO-10). File:line references are repository-relative.

## Findings that shape the plan

1. **`/admin/operations` is in no navigation.** `PILLARS` (`src/lib/navigation/pillars.ts:89-176`) has no operations entry and the inline `allNavGroups` in `src/components/layout/AdminShell.tsx:355-446` defines only Command, Pipeline, Clinical Ops, Quality & Risk, Knowledge, Workforce, Finance. Reachability at both role entry points needs navigation items, not only a route.
2. **No UI reads managed-occurrence data.** No file outside `src/app/api/` reads `occurrence_kind`, `execution_state` or `effective_receipt_id`, and no page calls the receipts, evidence or record endpoints. COL-148 is the first client of COL-139 through COL-146.
3. **Legacy complete refuses managed occurrences** (`tasks/[id]/complete/route.ts:10`). One-action Complete must branch: managed rows to the record command, legacy rows to the legacy route.
4. **List position is not retained today.** The operations page keeps filters in component state (`page.tsx:106-107`), and every action calls `loadData()` which flips `isLoading` and remounts the tree through the skeleton branch (`page.tsx:311`); no scroll restoration, focus return or URL state. The preserve-position behaviour is a deliberate build, not a port.

## 4. Inputs, evidence rules, receipts and evidence for the UI
