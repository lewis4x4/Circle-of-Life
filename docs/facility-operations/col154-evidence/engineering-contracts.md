## 2. Vocabulary

- **Final** (`finalized_at IS NOT NULL AND voided_at IS NULL AND deleted_at IS NULL`): the record has been committed by a person through the finalize (drill) or record (observation) command. Existence never implies finality; every `drill_log` row that exists before this migration, and every row the legacy page writes after it, is a **draft** until someone finalizes it.
- **Version** (`record_version`, integer from 1): bumped by the table's guard on every change to a content column, draft or final. A void does not bump it: the void delivery names the current version with `event_kind='voided'`.
- **Recording act** (`version_recorded_at`, `version_recorded_by`): the server instant and person who committed the current version — the finalizer for version 1 (or the recorder of an observation), the corrector for each later version. This pair is the source's `recorded_at`/`recorded_by` for 346, so the 346 late rule (fifteen minutes) and recorder-list check apply to the person who committed the version, exactly as they apply to a person recording by hand.
- **Entry reason** (`entry_reason`): the record's own stated reason when its performed instant is more than fifteen minutes before its recording act (late) or when the performer is another staff member (on behalf). The commands refuse to commit a version that needs one and has none, so the delivery is never refused for an unstated late entry.
- **Readings** (`readings jsonb`, default `{}`): typed values keyed exactly as the governing rule's inputs. They are passed verbatim as the statement's `values`; the rule (338 `required_inputs`) decides whether they are defined, required and in range. Nothing is inferred from legacy columns: **typed readings satisfy only where an approved rule defines them**.
- **Outcome**: drill `performed` | `failed`; observation `pass` | `fail`. `failed`/`fail` requires `issue_summary` and delivers as outcome `failed` with issue `{kind: failed_result, summary}`, so the occurrence stays `failed` and a 341 issue is opened; a `performed`/`pass` with an `issue_summary` delivers issue `{kind: problem}`. An issue opened by a source receipt stays open and bound to that receipt through later correction or void (COL-145 policy 3g(vi)); a void never closes it.
- **Basis** (`asset_observations.basis`, CHECK `staff_observed`): the record command accepts `staff_observed` only and refuses `automatic_self_test` and `photo_only` by name. A controller self-test log or a photo is supplementary evidence (COL-143) on the occurrence, never a source record.

### 3.1 `drill_log` additions

| `entry_reason text (≤2000)`, `correction_reason text (≤2000)` | |

| `readings jsonb NOT NULL DEFAULT '{}'` (object) | |

Content columns (version bump): `drill_type`, `drill_date`, `drill_time`, `pull_station_activated`, `staff_present_count`, `residents_present_count`, `conducted_by`, `notes`, `evidence_url`, `evidence_storage_path`, `readings`, `outcome`, `issue_summary`, `entry_reason`.

Guard (BEFORE INSERT/UPDATE/DELETE, replaces nothing): hard `DELETE` refused; `id`, `organization_id`, `facility_id`, `created_at`, `created_by` immutable; `organization_id` must be the facility's. Without the domain token (§3.5): an insert carries no lifecycle values; a draft may change content or be soft-deleted (legacy page behaviour kept); a **final** row refuses every content change (`Finalized drill logs change only through a correction`) and a soft delete (`Finalized drill logs are voided with a reason`); a **voided** row refuses every change. With the token: draft → final sets `finalized_*` and `version_recorded_*` together; final content change sets `version_recorded_*`; void sets `voided_*` on a final row; nothing un-finalizes or un-voids. Existing rows get `record_version=1`, no lifecycle values: they are drafts.

### 3.3 `operation_source_record_requests` (idempotency ledger for the domain commands)

`id`, `organization_id`, `facility_id`, `request_key UNIQUE` (341 regex), `request_hash`, `actor_id → user_profiles`, `actor_role`, `at`, `source_key`, `source_record_id`, `action` (`record`/`finalize`/`correct`/`void`), `source_event_id → operation_source_events` (NULL when nothing was delivered), `reply jsonb`. ### 3.5 Token

A third transaction-local setting `haven.operation_source_record_command`, compared with the same owner secret by `haven.operation_source_record_approved()`, marks the domain commands' writes to `drill_log`, `asset_observations` and the request ledger. It is set only inside the commands and cleared before they return; the 346 delivery sets and clears its own two tokens, so the domain writes are complete before the delivery runs.

## 5. Commands (session; `haven.*` definer with `public.*_review` invoker wrappers granted to `authenticated`)

Order in every command: shape (22023 before any row) → actor (managed, current site access through `haven.operation_facility_access`, session and grants locked `FOR SHARE` as 341 does) → advisory lock on the request key (record) or on the record id (finalize/correct/void) → replay by request key through §3.3 → record state → domain write under the domain token → token cleared → 346 delivery under the same actor with request key `<key>:deliver` → request row → reply. The delivery's own refusals are recorded rows, never exceptions; a delivery exception (a retired adapter, a request-key collision) rolls the whole command back, so no record is final without its delivery row.

- `record_asset_observation_review(p_request_key, p_payload)` — payload `{ facility_id, asset_id, observation_kind, observed_at, basis, observed_by?, outcome, readings?, issue_summary?, note?, entry_reason? }`. Refusals: `basis` other than `staff_observed` (`An automatic self-test is not a staff observation` / `A photo alone is not a staff observation`); asset not current at the site; kind/asset type mismatch (`A generator test is recorded against a generator`, `An extinguisher check is recorded against a fire extinguisher`); `observed_at` in the future; `fail` without `issue_summary`; late or on-behalf without `entry_reason`; `observed_by` not current staff at the site. Writes one final row (version 1) and delivers `final`.
- `correct_asset_observation_review(p_id, p_request_key, p_expected_version, p_payload)` — payload `{ reason, asset_id?, observed_at?, observed_by?, outcome?, readings?, issue_summary?, note?, entry_reason? }`; `p_expected_version` must be the current `record_version` (else `Record changed since it was read`, P0001, DETAIL `current_record_version=<n>`); a voided record refuses (`Observation is voided`). Applies the patch (version n+1, `version_recorded_*` = actor/now, `correction_reason`), re-checks §2 rules on the corrected content, delivers `final` for the new version: 346 corrects the earlier source receipt as a 344 correction, or — when the asset changed — invalidates the receipt on the first asset's occurrence and satisfies the second as a fresh chain.
- `void_asset_observation_review(p_id, p_request_key, p_payload)` — `{ reason }`; already voided refuses. Sets `voided_*`, delivers `voided` for the current version: the 346 reversal returns the occurrence to `pending`/`missed` and leaves the `invalidated` attention row; the issue stays open.
- `finalize_drill_log_review(p_id, p_request_key, p_payload)` — `{ entry_reason? }` (when given, stored before the checks). Requires a draft at a site the actor holds; already final refuses (`Drill log is already final`); voided refuses. Checks: drill instant ≤ now + 2 min; late/on-behalf → `entry_reason`; `failed` → `issue_summary`; `conducted_by` current staff at the site when set. Sets `finalized_*` and `version_recorded_*`, delivers `final` — except `tornado`, which is finalized and returned with `delivery: null, linked: false, link_reason: no_checklist_activity`.
- `correct_drill_log_review(p_id, p_request_key, p_expected_version, p_payload)` — `{ reason, drill_type?, drill_date?, drill_time?, pull_station_activated?, staff_present_count?, residents_present_count?, conducted_by?, notes?, readings?, outcome?, issue_summary?, entry_reason? }`; final and not voided; expected version as above.
- `void_drill_log_review(p_id, p_request_key, p_payload)` — `{ reason }`; final and not voided.

Reply: `{ record, delivery, linked, replayed }` where `record` is the row after the command, `delivery` the 346 reply (`event`, `occurrence`, `receipt`, `candidates`, `replayed`) or NULL, `linked` is true only when `delivery.event.state` is `satisfied` or `corrected`. Whether the record links is decided by 346 (`unmatched` when no rule or occurrence exists, `recorder_not_authorized` with attention when the finalizer is outside the published recorder list, `conflict` when a person or another record already satisfied the occurrence); the command never hides that outcome and never re-tries it — reconciliation is the 346 `retry`/`select`/`dismiss` under the COL-133 scope.

Authority: any managed actor with current site access on the record's site may record, finalize, correct or void (the operations roles `haven.operation_facility_access` admits). Whether that person may *satisfy* the occurrence is the governing rule's recorder list, applied by 346 to the recording act. No manager gate is invented (Q29 open, as COL-145 3g(i)).

## 8. Boundaries kept
