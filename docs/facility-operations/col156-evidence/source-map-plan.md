## Shared API and presentation proposal

Read through existing EmployeeFile API and current actor/RLS. Add an operations projection only if needed to associate canonical activity_key and employee subject with existing requirement/record references. UI must consume server-authorized employee scope, minimal per-field readiness/expiry/provenance, and explicit unavailable/unknown reasons. No second HR checklist, clinical form, eligibility engine or automatic performance receipt. Datafields display native facts; linked actions navigate to existing authorized employee workflow; record_review still requires actual human review if separately governed.

Use existing latestRequirements/assessEmployeeFile semantics: latest approved applicable version; newer draft cannot replace published; retired newest cannot resurrect old; verified completed_on must not be future; expires_on and recurrence unknowns preserved. Source updates should invalidate/refresh projection once by version/record identity; replay does not duplicate records or HFO performance. Required signatures and actual evidence remain native.

Medical fields must redact value, completion/expiry dates and sensitive record metadata for unauthorized actors. A category=training draft TRN25/26 cannot establish medical access. DOC039/040 medical classification is relevant source evidence, not permission to silently migrate existing records. New approved classified versions require attributable review. Personnel and medical evidence use existing separate buckets and current medical grant path; protected source downloads reauthorize current employee/site/medical scope.
